# 架构与迁移记录

## 技术选型

统一使用 TypeScript、Node.js 22+、Fastify 5。三个平台均通过 Node.js 原生 fetch 发起 HTTP 请求，企查查使用 Cookie + HTTP。使用同一语言处理请求签名、API 和类型定义，避免维护 Python 与 JavaScript 双运行时。

调用链：API 参数校验与鉴权 → 指定来源的 Provider（lookup 由 `src/lookup.ts` 按顺序或并行调用多个 Provider，并做精确匹配与字段对比）→ HTTP → 协议及业务状态校验 → 平台字段归一化 → 统一响应。

查询必须明确指定来源。各平台 ID 保持字符串，不推断跨平台身份，不将多个来源的数据静默拼接。不支持的能力返回 UNSUPPORTED；受限查询返回明确错误，不能伪装为空结果。

## 已完成迁移范围

- 天眼查：搜索、企业详情、Cookie 到认证请求头的映射、过滤非企业卡片及去除高亮标签。
- 企查查：HMAC-SHA512 动态请求头，HTTP 搜索及页面初始数据详情；只访问固定源站与已允许的业务路径。
- 爱企查：搜索、详情、slug 同源跳转解析、DDW 数字还原。元数据与企业数据分开处理；未知 DDW 编码直接报错。
- API：统一查询结果、错误分类、鉴权、限流、输入校验与可选原始响应。
- 工程：构建、类型检查、离线测试、Docker、Compose、GitHub Actions。
- 统一模型：基础字段保持兼容；增加 15 个工商扩展字段和模块状态。按已验证数据归一化股东、人员、分支和年报索引，投资/变更明细映射仍未验证；见 [字段映射](field-mapping.md)。Provider 工厂及来源能力集中到 `src/registry.ts`。

原 Python 脚本仅用于迁移对照。最终 Corpix 不保留 Python 文件或 Python 运行依赖，也不保留原始 Cookie、抓包、线上网页及第三方 JS 副本。迁移之前的原始资料仍位于用户的 Demos 目录，未作修改。

## 发布前的事实边界

适配依据为 2026-11-03 本地研究报告。2026-11-19 使用迁移后的 TypeScript 适配器联网验证天眼查匿名首屏搜索（20 条）及数字 ID 详情（1 条），均成功；未使用个人 Cookie，未保存真实响应。该结果不代表其他关键词、分页或账号权限的覆盖。本版本的 CI 仅使用合成数据和独立签名向量。早期的企查查 CDP 浏览器模式从未完成真实会话实测，已在 Cookie + HTTP 验证通过后删除。

2026-11-19 后续已将企查查 Cookie + HTTP 和爱企查搜索接入正式 API，并以四家企业 × 三平台完成 12 组搜索/详情验证，见 [多公司验证元数据](platform-multisample-verification.json)。单平台接口不在平台之间自动回退，跨平台兜底只在显式调用 lookup 时发生。天眼查后续分页、企查查账号权益等由源站决定；嵌套模块列表可能被截断或附有权限标记，不能将空数组泛化为没有相关记录。

## 后续优先级

1. 在授权环境中分别验证匿名查询、有效登录态、会话过期和账号权限不足，记录验证日期及结果。
2. 按实际请求补充匿名化回归样本，并核验 Docker 构建和运行。
3. 在字段协议稳定后增加 OpenAPI 文档及可独立发布的 SDK。
4. 有明确使用场景时扩展股东、高管、投资与变更模块，继续保持来源及权限边界。
